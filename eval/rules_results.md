# ルール層（Verification Engine の D）の実測

実行: 2026-11-09 12:26。AI を使わない決まった動きのコードなので、何度流しても同じ結果になる。
対象: `eval/ussa_cases.py` の PRECISION 20 件（日本語・中国語・英語・ベトナム語）。正しい訳と、誤りを1つ入れた訳を人が書いた。

| 指標 | 結果 |
|---|---|
| 誤りを入れた訳を「強い不一致」として検出 | 13 / 20 |
| 正しい訳を誤って「強い不一致」とした（誤警報） | 0 / 20 |
| 否定の反転に「弱い証拠」（否定の有無の違い）を出した | 5 / 5 |
| 正しい訳にも「弱い証拠」が出た（弱い証拠だけでは止めない理由） | 1 / 20 |

誤りの種類ごと（検出数 / 件数）:

| 種類 | 検出 |
|---|---|
| clock | 1 / 1 |
| condition_missing | 1 / 2 |
| frequency | 2 / 2 |
| negation | 0 / 5 |
| quantity | 4 / 4 |
| quantity_omission | 1 / 1 |
| quantity_swap | 0 / 1 |
| time | 3 / 3 |
| weekday | 1 / 1 |

ルール層だけでは見つけられないもの: 否定の反転（字面の否定は「弱い」証拠として扱い、枠の比較と LLM の照合で判断する）、条件の欠落（数を含まないもの）、数の入れ替え（同じ数の組のまま位置が入れ替わる）。これらは B・C の層の役割で、本物の Gemini での実測は `eval/compare.py --live`（未実施）。
