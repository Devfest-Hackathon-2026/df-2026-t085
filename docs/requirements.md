## 1. 何を作るか

**UNSAID**：日本語を話す医師と、日本語が話せない外国人患者の問診を支える Web アプリ（カテゴリ：医療・福祉）。

- 患者が言った言葉のうち、**意味がぶれる言い方**（「しばらく」「ときどき」など）を Gemini が見つけ、**患者の言語で1つだけ**確かめる。
- 患者は、医師にどう伝わるか（逆翻訳）を**自分の言語で確認してから送る**。
- 患者のスマホと医師の PC の **2台がリアルタイムに同期**する。
- **診断はしない。** AI がするのは「意味の確認」と「翻訳」だけ。

### 一般的な翻訳アプリ（VoiceTra 等）との違い

| | 翻訳アプリ | UNSAID |
|---|---|---|
| 曖昧な言い方 | 曖昧なまま訳す（医師は気づけない） | 送る前に患者に確かめ、確定した意味で訳す |
| 伝わり方の確認 | 話した本人は訳文を読めない | 逆翻訳を患者の言語で見てから送る |
| 医師の画面 | 訳文だけ | 「確認済み」の印と、何をどう確かめたか（例：「しばらく」→約1週間） |

デモの最初の10秒でこの差を見せる（[6. デモ](#6-デモ)）。

### しないこと

- 診断・病名の推定・治療の提案
- 感情認識（EU AI Act でリスクが高い分類のため）
- 音声の保存（文字起こしの後に捨てる）

## 2. 利用者と前提

| 役 | 言語 | 端末 | 前提 |
|---|---|---|---|
| 医師 | 日本語（`doctorLang = ja` 固定） | PC（診察室） | PC には電子カルテが映っている。患者に画面を見せたくない |
| 患者 | 外国語（`en` / `zh-CN` / `vi`。デモの言語は **TBD**） | 自分のスマホ | アプリは入れない。QR を読むだけで使える |

- 確認質問は**患者の発言にだけ**出す。医師の発言は翻訳だけ（確認なし）。
- 確認質問は患者の言語で出す（日本語が混ざったら失敗扱い。test.py で検査）。

## 3. 使う流れ（デモで通す1本）

```
医師 PC                                   患者スマホ
1. 「問診を始める」→ QR を全画面で表示
                                          2. QR を読む → 言語を選ぶ → 参加
3. QR が自動で閉じる（カルテは映らない）
                                          4. 押して話す → 文字を確認・修正 → 送る
                                          5. 曖昧な所があれば：ハイライト＋質問1つ＋大きな選択肢
                                             （「うまく説明できない」「自分で書く」も選べる）
                                          6. 「医師にはこう伝わります」（逆翻訳）を見て「送信」
7. 日本語訳＋「確認済み」＋確かめた内容を表示
   問診メモ（facts）に項目が増える
8. 医師が話す（日本語）→ 翻訳して患者へ
                                          9. 患者の言語で表示
（4〜9 をくり返す）
```

### 3.1 セッションと参加（QR）

- **QR は問診ごとに1つ。** 医師が `createSession()` で作り、患者が読んで `joinSession(sid, lang)` で参加する。
- 参加できるのは 2人目まで・作ってから 30分以内。患者の言語は参加時に1回だけ書け、後から変えられない（`firestore.rules`）。
- QR はリポジトリ内のライブラリで作る（外部の QR API に session id を渡さない）。
- **医師ごとに固定の QR は採用しない（11/8 決定）。** 理由：QR が永続の合言葉になる、待合で誰が入ったかを医師が承認する画面が要る、そもそも患者の身元を持たないので履歴の役に立たない。
- **医師 PC は QR を全画面で出し、患者が参加したら自動で閉じる（11/8 決定）。** 電子カルテを患者に見せないため。

### 3.2 発言の状態

```
患者: analyzing → clarifying（質問あり）→ confirmed → sent → received
                 └ 質問なし ───────────→ confirmed
医師: analyzing → sent
失敗: error（「もう一度」で同じ API を呼び直す）
```

画面ごとの表示は [api.md の「状態ごとの画面」](api.md#状態ごとの画面)。

## 4. 画面（UI 案B、11/8 決定）

モック：https://claude.ai/artifact/WE4NWy1T5GhHfiCZfF6f7x （案B v2）。方針は **病院で使うので情報は最小限**。担当は Yusei。

### 患者スマホ（1画面に1つのことだけ）

- 話す画面：大きなマイクボタン。文字入力も必ず残す。
- 確認画面：曖昧な語をハイライトし、質問1つ＋画面幅いっぱいの選択肢4つ。タップで即回答（「次へ」なし）。「うまく説明できない」「自分で書く」は文字リンク。
- 送信前：逆翻訳を大きく表示＋「送信」。
- 待ち時間：「確認しています…」「翻訳しています…」を出す。質問は onSnapshot で表示する（API の応答を待たない）。

### 医師 PC

- 患者の最新の発言（日本語訳）を大きく。`確認済み` の印＋1行（例：「しばらく」→約1週間）。
- 原文はボタンで開く。`translation.note`（「患者は説明できなかった」等）があれば注意書き。
- 右側に問診メモ（facts から、埋まった項目だけ）。患者が確認中なら「確認中…」の行。
- 大きなマイクボタン（医師の音声入力をデモで使うかは **TBD**）。
- 開始時は QR の全画面表示（3.1）。

## 5. 技術構成

```
患者スマホ / 医師PC（Firebase Hosting: web/）
   │  Firestore（onSnapshot で2台同期、匿名ログイン＋メンバーだけ読めるルール）
   │  HTTP（Firebase ID トークン）
   ▼
Cloud Run: unsaid-api（FastAPI, asia-northeast1）
   ├ /transcribe → Cloud Speech-to-Text v2（Chirp 3, us）
   ├ /analyze    → Vertex AI Gemini（clarify / facts / 先回り translate を並列）
   └ /translate  → Vertex AI Gemini
```

| 部品 | 決めたこと | 理由の詳細 |
|---|---|---|
| 実行基盤 | Cloud Run（API）＋ Firebase Hosting（画面） | [api.md](api.md#構成の選び方own-the-why) |
| LLM | Vertex AI `gemini-3.8-flash`、location `global`、`generate_content`、`thinking_level="low"`、`response_json_schema` で JSON 固定 | クレジット $20 は AI Studio に使えない。[ai-pipeline.md](ai-pipeline.md) |
| プロンプト | 英語のシステムプロンプト1本、言語はリクエストで渡す。言語追加は `LANGS` / `FIXED_OPTIONS` / `STT_LANGS` に1行ずつ | [ai-pipeline.md](ai-pipeline.md#多言語化のための設計判断own-the-why) |
| 確認質問 | 最大1つ。対象は「意味」がぶれる語で、特に時間・頻度。患者が言った体の部位を絞らせる質問はしない。程度の語（"a little"）を対象にするかは **TBD** | [ai-pipeline.md](ai-pipeline.md) |
| 翻訳 | 確認の後に別呼び出し。`back_translation` と `note` を返す | [ai-pipeline.md](ai-pipeline.md) |
| 音声入力 | Speech-to-Text v2 Chirp 3。文字を患者が直してから送る。Web Speech API と Gemini への音声直渡しは不採用 | [stt.md](stt.md) |
| データ | Firestore（asia-northeast1）。`sessions/{id}` と `sessions/{id}/messages/{id}`。Gemini の結果はサーバーだけが書く | [api.md](api.md#メッセージのフィールドsessionssessionidmessagesmessageid) |
| 認証 | 匿名ログイン＋ members によるルール（医師のログイン方法は **TBD**） | `firestore.rules` |

### 非機能

| 項目 | 目標・現状 |
|---|---|
| 待ち時間 | STT 約1.3秒＋確認質問まで Gemini 1回分（目安 3〜7秒）。質問を先に書き、facts は後から届く |
| 失敗時 | Gemini は 12秒で打ち切り1回打ち直し、429 は指数バックオフ。最後は `status: error` →「もう一度」 |
| コールドスタート | デモ当日（11/10、11/14）だけ `--min-instances 1` |
| 個人情報 | 音声は保存しない。メッセージはそのセッションのメンバーだけが読める。外部 QR API を使わない |
| 費用 | クレジット $20 の中。予算アラート ¥2,000 |
| 秘密情報 | 提出リポジトリは公開。鍵はコミットしない（firebaseConfig は公開前提の値） |

## 9. 将来の拡張（スライド用、今回は作らない）

- **履歴の参照**：医師の session 一覧（`members` に医師の uid を含む session）＋医師だけが書ける受付番号メモ → 電子カルテとつなぐ入口。
- **受付タブレットで QR を発行**／待合で先に話し始める（ルールは 3人目のメンバーに対応が要る）。
- **オンライン診療**：2台同期の仕組みはそのまま使える。
- **多言語の追加**：言語ごとに設定を1行足すだけ（プロンプトは共通）。
- **電子カルテ連携**：問診メモ（facts）を構造化データとして渡す。
- **国際版お薬手帳**：確認済みの内容を患者の言語と日本語の両方で持ち歩く。
