# 実装状況（USSA の各コンポーネントと、何で確かめたか）

2026-11-10 時点、`feature/unsaid-clinical-meaning`。ARCHITECTURE.md の仕様に対して、コードを読んで点検した結果。
**「動く」と「正しく判断できる」を分ける。** 判断の多くは Gemini が行う。本物の Gemini では 2026-11-10 に、評価用のプロジェクトで各コンポーネントの基本動作と
4 方式の比較を行った（EVALUATION.md 4）。下の「LLM」の列の判断の質は、その 108 件の模擬症例の範囲でだけ分かっている。偽の AI（`devtools/fake_ai.py`）はデモの数文の答えを決め打ちで返すだけなので、
偽の AI で通ったことは「サーバーの検証・状態遷移・画面の流れが動く」ことの証拠であって、「意味を正しく判断できる」ことの証拠ではない。

## 区分

- **コード**: 決まった動きのコード。単体テストで入力を固定して確かめた（AI が無くても同じ結果）。
- **LLM**: Gemini の出力に依存する判断。コード側は出力をスキーマと原文の引用で検証して、使えないものを捨てる。**判断の質は未検証**。
- **名前だけ**: 名前や画面があるのに中身が無いもの。点検した範囲では見つからなかった（下の表の「仕様との差」に、足りない所を書く）。

## コンポーネント

| コンポーネント | コード（確かめ済み） | LLM（判断の質は未検証） | 仕様との差・注意 |
|---|---|---|---|
| Speech & Input | 録音・WAV 化・送る前に直せる入力欄（`web/stt.js`、`stt.py`） | 音声認識（Chirp 3） | このブランチでは本物の音声認識を通していない |
| Source Agent | 出力の検証（`ussa.build_intent`: 列挙・選択肢が発言者の言語か・原文に実在する根拠） | 発話意図・意図が文脈で決まるか・意味の枠 A | 「本人に聞くべきか」の判断は Gemini 任せ。聞きすぎ・聞き漏らしの率は未測定 |
| Translation Agent | 文脈・本人が確認した意図・照合の指摘を渡す組み立て（`main._draft`） | 翻訳そのもの | — |
| Semantic Bridge | 枠の正規化（`ussa.build_frame`: 日時・数量・回数・列挙）と比較（`ussa.compare_frames`） | 枠の抽出（A: Source Agent、B: 訳文だけから `frame_extract`） | 別の言語を経由する「中間言語」ではなく、意味の枠を比べる仕組み。比較はコードだが、比べる枠は Gemini が作る |
| Verification Engine | D: ルール照合（数・時刻・日付・曜日・否定。`ussa.rule_check`、20 件の正解つきで実測: EVALUATION.md 3）、統合（`ussa.combine`: 強い証拠は LLM の「同じ意味」で消えない）、訳し直しと再照合の回数制限 | B の枠、C の直接照合 | 本物の Gemini で、誤りを入れた訳 20 件の見逃し 0/20（3 回の繰り返しで 0/60）、正しい訳の誤警報 1/20（2/60）。D だけで見つけられないもの（否定の反転・数を含まない条件の欠落）は B・C 頼み |
| Safety Gate | すべてコード: 状態遷移（`ussa.GATE_TRANSITIONS`）・送る直前の 8 項目のチェック（`ussa.send_checks`）・トランザクションで読み直して送る（`main._deliver`）・古い解析は run_id で書かない | なし（LLM の「安全」は根拠にしない） | 端末の直接書き込みで迂回できないことを Firestore エミュレーターの本物のルールエンジンで確認。本番のプロジェクトのルールは未確認（このブランチのルールは本番に公開していない） |
| Clarification Manager | 2 種類の確認の状態遷移（`clinical.py`、`ussa.confirm_intent`）、確認質問の Gate 経由の送信、答えの結びつけ（送った順・重複なし・医師の判断の後の答えは「再確認が必要」） | 確認候補と選択肢の生成（Meaning Engine） | — |
| Conversation Auditor | 説明と言い直しの照合（`ussa.cross_check`）、提案の検証（実在する発言 id と引用）・重複の除去・AI は ANSWERED までの制限（`ussa.merge_audit`）、記憶の上限 20 件（指示を優先） | 矛盾・理解の相違・未回答・説明不足の検出 | 検出の質は未測定。偽の AI ではデモのシナリオの指摘しか出ない |
| 双方向の意図確認 | 患者 → 医師、医師 → 患者の両方で、意図が決まらなければ翻訳せず本人に聞く（サーバー・両方の画面。`tests/test_gate_flow.py` で両方向） | 意図が決まるかの判断、解釈の候補 | 実際の会話でどれだけ聞くかは未測定 |
| Clinical Memory | 原文との突き合わせ（引用が実在しなければ捨てる）、状態と履歴、カルテ用の文章 | 情報の抽出 | — |
